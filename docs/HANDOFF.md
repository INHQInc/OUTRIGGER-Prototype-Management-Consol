### PINNED — designed with the user 2026-08-06, deliberately NOT built yet

**METRIC ROLES + OPERATIONAL DEFINITIONS.** Bryan's idea, worked through to a design he chose to park. Do not start it without him. The design, so it survives:

- **The tier model.** Today a metric is primary or it is background. The missing tier is **secondary** (the industry/clinical word — *secondary endpoints*; his phrasing was "supporting metric"). Four roles: **decision/primary** (exactly one, full alpha, what the verdict adjudicates) · **secondary** (pre-registered, chosen because it supports or explains the hypothesis; reported, FDR-corrected, never decisive alone) · **guardrail** (veto power, no promotion power — exists) · **exploratory** (the default; interesting, never evidence). The beats row in WHAT WE'RE SEEING becomes decision + declared secondaries **in the user's `measureOrder`**, replacing today's arbitrary first-three.
- **Do NOT build the standalone wizard.** He first proposed a first-visit-to-Analytics wizard walking every metric. Rejected in conversation for two reasons: (1) the readout would already be on screen behind it, so classification is post-hoc — the exact laundering the tier exists to prevent; (2) eleven cards at the moment of peak impatience produces **rubber-stamped pre-registration, which is worse than none** — a readout citing eleven "human-ratified" definitions nobody read. Instead **fold roles + definitions into measurement-plan confirmation**, which is already the pre-traffic ceremony with a stamp and a disclosure path (`plannedAt`, `priorConfirmations`, `mapConfirmedAfterObservation`). One gate, one stamp. Confirming the plan then IS pre-registration, and the `not_adjudicable` state resolves in the same click.
- **Friction proportional to the claim.** Everything defaults to exploratory and costs nothing. Secondary costs one sentence. Lazy path = two screens (confirm the decision metric · multi-select which metrics support the hypothesis); only the selected ones ask for text. **Secondary must stay scarce** — past ~4 the flow pushes back and asks which actually test the mechanism. Otherwise secondary decays into "exploratory with a nicer badge".
- **Operational definition** (the scientific term for his "quick summary of what the metric is measuring") — what exactly counts as one occurrence. Required only where a human created the meaning: **composites, renames, anything with `armEvents`**. Pass-through Optimizely metrics derive theirs; asking for text there is busywork. The definition is not documentation: it feeds `deepObservation()`, the reading, and the printed record — it is the fix for the analyst inferring meaning from a metric's name (the root of the "metric is not wired" complaint on a metric that was reporting fine).
- **AI drafts, human ratifies, provenance discloses.** The draft is grounded in real bindings (events, arms, brief) so it drafts something true. A definition stays marked **AI-drafted until edited**, and the readout can tell the difference. Disclose rather than block — same law as the mid-run metric swap.
- **Post-hoc promotion is allowed, recorded, and never laundered.** A metric promoted to secondary after observation is disclosed and never sits in the beats row as though pre-registered (reuse the `primaryChangedAfterObservation` pattern). Otherwise the tier becomes "metrics that turned out well".
- **Card zero:** *"Optimizely's primary is <name> — is that the decision metric?"* Confirming or overriding it there is what would have prevented the planner inventing an untracked metric when the primary was ambiguous.
- **Later-born metrics** get the same two questions inside `MetricBuilder` at creation — not a re-run of the flow. A metric whose events change loses its ratified definition and needs re-ratification (which also kills the stale cached deep read listed in the open findings above).
- **What it buys on screen:** an ordered, meaningful beats row; observations that stop guessing what a metric means; and a verdict line that can finally say *the secondaries corroborate* or *they don't* — the sentence an exec actually needs.
